# 泊影 Framemoor 1.0.0

## 简体中文

泊影 1.0.0 是首个正式版，是面向影视制作和个人创作者的免费开源拷卡工具。它从存储卡或文件夹导入照片与视频，按设置好的目录和文件名整理素材，默认使用 SHA-256 检查复制内容。

### 本版更新

- 简易视图与详细视图的视频编码选项都增加 **RAW（全部类型）**，可同时选择已识别的 Canon RAW、Blackmagic RAW、REDCODE RAW、Nikon N-RAW、ARRIRAW、ProRes RAW、Sony X-OCN 与 Cine RAW，目录中继续使用具体编码名称。
- 扩展 RAW 视频分类和编码读取，避免预览轨道遮住文件中的 RAW 轨道；同组素材中任一视频符合筛选时，已经关联的同名代理文件一并保留。
- 扩展照片 RAW 分类并增加 Insta360 INSP 照片识别。文件内容优先于扩展名，无法确认的视频编码保留 `Unknown`。照片勾选项独立于 RAW 视频筛选，CinemaDNG 的 DNG 帧仍按照片导入。

完整格式与条件见[素材格式与识别范围](../media-formats.zh-CN.md)。RAW 识别用于分类与复制，不包含解码、播放、转码或序列合成。

### 导入功能

简易视图将来源、目标、日期范围、素材类型和预设放在同一页；详细视图分为来源、筛选、预设、预览和导入五步。目录层级和命名规则可编辑，变量支持点选和帮助说明，预设只保存规则，应用后重新填写内容名称。最终预览提供目标目录树、文件列表、冲突和空间检查。

拍摄时间默认保留相机记录，也可以按记录的 UTC 偏移转换到指定 IANA 时区，或手动校正分钟数。首次参考系统时区，此后记住选择，拍摄地需要自行确认。时间规则用于筛选和归档，不修改文件内的拍摄元数据。

来源以只读方式访问，已有目标文件不会被覆盖。导入支持暂停、恢复、任务历史和 JSON 报告；SHA-256 校验默认开启，可设置读取并发数，也可关闭校验。关闭后界面持续提示可靠性降低，相关任务与报告明确标为未校验。设置还包含中英双语、浅深色外观、默认目标与预设、完成通知及导入期间防休眠。每次扫描重新读取来源，不使用持久化扫描或校验缓存。

### 安装包

- **macOS Apple Silicon：** `.dmg`，要求 macOS 13 或更高版本。应用采用 ad-hoc 签名，未使用 Apple Developer ID 签名或公证，首次启动可能被 Gatekeeper 拦截。
- **Windows x64：** NSIS `-setup.exe`，要求 Windows 10 1903 或更新版本／Windows 11，以及 WebView2。安装包未签名，可能出现未知发布者或 SmartScreen 提示。

下载见 [GitHub Releases](https://github.com/wzk112/Framemoor/releases)。发行附件同时提供对应源码、依赖声明和 SHA-256；暂不提供 Intel Mac 或 Windows ARM64 安装包。

### 验证范围

现有 macOS 真实素材测试包括 Canon EOS R5 Mark II。分类回归使用合成元数据和随包 ExifTool 读取的合成文件，浏览器测试使用模拟 IPC，Windows CI 则在 Windows Server 虚拟机中安装实际应用，通过真实 WebView2 测试界面与导入。Blackmagic RAW 的 `brhq` 标记有一个厂商附带 BRAW 样例的只读解析证据；真实 NEV 文件读取、其他品牌素材和 Windows 实机仍需验证。

这些结果不能替代对所有机型、读卡器、拔卡、掉电、网络卷和完整拍摄包关系的测试。最终安装包对应的提交与检查结果记录在本次 Release 的构建记录中，验证方式见[发行打包与验证](../release-validation.md)。原创代码采用 **GPL-3.0-only**，第三方组件保留各自许可证。

## English

Framemoor 1.0.0 is the first stable release of this free, open-source media ingest tool for film production and personal creators. It imports photos and videos from memory cards or folders, organizes them using configurable folders and filenames, and verifies copied content with SHA-256 by default.

### Changes in this release

- Both simple and detailed views offer **RAW (all types)** in video codec selection. It selects recognized Canon RAW, Blackmagic RAW, REDCODE RAW, Nikon N-RAW, ARRIRAW, ProRes RAW, Sony X-OCN and Cine RAW while retaining concrete codec names in destination folders.
- Expanded RAW video classification and codec reading so preview tracks do not hide a RAW track in the same file. When any video in a group matches the filter, already-associated same-name proxies remain included.
- Expanded photo RAW classification and added Insta360 INSP photos. File content takes priority over extensions; uncertain video codecs remain `Unknown`. Photo selection is independent of the RAW video filter, and CinemaDNG frames continue to import as photos.

See [media formats and recognition](../media-formats.md) for the complete list and conditions. RAW recognition covers classification and copying, not decoding, playback, transcoding or sequence assembly.

### Import workflow

The simple view combines source, destination, date range, media types and preset on one page. The detailed view uses five steps: source, filter, preset, preview and import. Directory levels and naming rules are editable, with clickable variables and help. Presets store rules only and clear the shoot description when applied. The final preview includes a destination tree, file list, conflict checks and space checks.

Capture time defaults to the camera's recorded time. It can also be converted from the recorded UTC offset to an IANA time zone, with optional manual minute correction. The app initially suggests the system time zone and remembers later choices; the shooting location still needs confirmation. These rules affect selection and filing without modifying embedded capture metadata.

Sources are read-only and existing destination files are not overwritten. Imports support pause/resume, task history and JSON reports. SHA-256 verification is enabled by default, with configurable read concurrency and an option to disable it. Disabling verification displays a persistent reliability warning and marks tasks and reports as unverified. Settings also include Chinese/English, light/dark appearance, default destination and preset, completion notifications and sleep prevention during import. Each scan rereads the source, without persistent scan or checksum caching.

### Packages

- **macOS Apple Silicon:** `.dmg`, requiring macOS 13 or later. The app uses ad-hoc signing without Apple Developer ID signing or notarization; Gatekeeper may block the first launch.
- **Windows x64:** NSIS `-setup.exe`, requiring Windows 10 1903 or newer / Windows 11 and WebView2. The installer is unsigned, so unknown-publisher or SmartScreen warnings may appear.

Downloads are on [GitHub Releases](https://github.com/wzk112/Framemoor/releases), alongside corresponding source, dependency notices and SHA-256 checksums. Intel Mac and Windows ARM64 installers are not provided.

### Validation scope

Existing real-media tests on macOS include Canon EOS R5 Mark II. Classification regressions use synthetic metadata and synthetic files read by packaged ExifTool. Browser tests use mocked IPC, while Windows CI installs the actual app on a Windows Server VM and exercises its interface and import workflow through real WebView2. Blackmagic RAW's `brhq` identifier has read-only parsing evidence from one vendor-bundled BRAW sample. Real NEV parsing, additional camera media and physical Windows PCs still need validation.

These results do not replace testing of every camera model, card reader, card removal, power loss, network volume or complete camera-package relationship. The final package revision and checks are recorded in this release's build records; see [release packaging and validation](../release-validation.md) for the methods.
